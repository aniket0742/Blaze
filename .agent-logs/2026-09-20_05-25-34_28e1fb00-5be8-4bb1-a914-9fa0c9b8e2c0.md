Fixed — one line, one file.

**The change:** [site-header.tsx:66](components/site-header.tsx#L66), `hover:bg-surface-strong` → `hover:bg-background`.

**Why that token:** the nav strip is `bg-surface` (`#f2f4f6`), so the hover colour had to differ from that. Of the two existing tokens that qualify, `background` (`#ffffff`) matches the depth model globals.css already states — white surfaces lifting off grey — and reads as the tab lifting rather than dimming. It also pairs with the `hover:text-foreground` already on the same element, so the whole hover state moves in one direction. The alternative, `border-subtle` (`#e4e7ec`), would darken instead; it works, but it inverts the established language. No new token, no design change.

**Verified:** `surface-strong` now appears nowhere in the codebase. Lint clean, build clean, all 223 pages still generating. In the production CSS the rule is now actually emitted — `.hover\:bg-background:hover{background-color:var(--background)}` — which is the substance of the fix: an undefined token produced no rule at all, so the hover was silently dead.

I did not add a DECISIONS.md entry. This is a bug fix inside the existing system rather than a design decision, and the reasoning above fits in the commit message.
