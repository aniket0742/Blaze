# CLAUDE.md

Project: **Blaze** — a modern ecommerce storefront (8x assignment).

## How we work

- Work in one coherent milestone at a time. Before each milestone, tell Aniket the plan and scope.
- Within an approved milestone, implement and test all parts autonomously. Do not begin the next milestone until he reviews and approves the current one.
- Keep code short, readable, and easy to review. Prefer simple functions and small files over clever abstractions.
- No code "for later."
- If something he asks for is a bad idea, push back and explain why.
- Do not make product or scope decisions on his behalf.
- If you need anything from him (credentials, configuration, clarification, a product decision, or manual action), say so explicitly before proceeding.
- **Do not create Git commits.** He reviews and commits himself.
- After each meaningful milestone, report what changed, what he should verify, and give one concise conventional commit message ready to use.
- Keep code changes and `.agent-logs/` together in the same commit whenever practical.
- Never put secrets in code or committed files. Keep `.env` files gitignored.
- **Never edit, clean up, summarize, or delete `.agent-logs/`.** It is the graded record of how this project was built.
- Ask before adding any dependency, service, or technology outside the agreed stack.

## Docs to maintain

- `DECISIONS.md` — important design/engineering decisions, why we made them, and what we rejected. Add entries as decisions happen.
- `README.md` — short and scannable: live link, demo login, what's built, what was deliberately left out, improvements over Amazon, and local setup. Update it as we go.

## Naming

The product is **Blaze**. Never use the Amazon name, logo, or visual design. Blaze follows the same broad "A-to-Z" product philosophy — a marketplace spanning many categories — as a product principle only.
